## 仕様 (#1〜#5)

### 1. シーンプリセット名の日付既定値

プリセットを選んでいないときだけ、保存名の既定値を日時にする。読み込み済みのプリセットがあるときは、上書き保存しやすいように従来どおりその名前を出す。

- 日時の書式は `yyyyMMdd_HHmmss`（例: `20260928_153012`）。プリセット名にはドットとファイル名の禁則文字を使えないので、数字とアンダースコアだけにする
- 名前欄の右に「日付」ボタンを置く。押すとその時点の日時の名前に置き換わり、検証エラーの表示も消える
- 日付の後ろに文字を足すときは、名前欄を直接編集する。専用の入力欄は作らない
- 同じ秒に 2 回保存すると同名になるが、既存の上書き確認ダイアログが出るので追加の対策はしない
- 保存形式と設定ファイルは変わらない

### 2. GameView の表示比率とサイズ指定

RT は今のまま画面解像度で描き、GameView へ描くときに中央を切り出して比率を表す。メインカメラも画面解像度のままなので、ゲーム側のカメラ操作（画面中央を注視点とみなす）は崩れない。

| 選択肢 | 表示 | スクリーンショットの出力サイズ |
|---|---|---|
| 画面（既定） | 切り出しなし | 画面解像度 × 倍率（従来どおり） |
| 16:9 / 4:3 / 1:1 / 3:4 / 9:16 | 画面からその比率を中央で切り出す | 切り出した範囲 × 倍率（例: 1920×1080 画面で 3:4、2 倍 → 1620×2160） |
| カスタム（幅 × 高さ、各 1〜8192） | 指定した幅と高さの比率で切り出す | 指定サイズちょうど。倍率は使わない |

- 比率が画面より横長なら上下を、縦長なら左右を切る。GameView ウィンドウの余りは従来どおり背景色で塗る
- カメラ操作・ドラッグ点・ギズモ・ボーン選択のマウス座標は、切り出し後の表示領域を基準にする。切り出しの外側はシーン操作の対象外
- 構図用の画面分割グリッドは、切り出した範囲の中を等分する
- カスタムの撮影は、画面の比率で描いて中央を切り出す（連番出力と同じ方式）。GameView の見た目と同じ構図になる
- 描画サイズが GPU の上限を超えたら、描画と出力を同じ割合で縮める
- 最大化中とウィンドウ一時非表示中は切り出さない（画面全体）
- 設定は保存する。変更は GameView のツールバー（比率のみ）と、設定ウィンドウのスクリーンショット節（比率・カスタムの幅と高さ・出力サイズの表示）から行う
- プリセットのサムネイルと連番画像出力のサイズ指定は変えない

### 3. 背景・モデル・PNG の非表示と透過撮影

背景・モデル・PNG を、メインカメラの描画からだけ外せるようにする。通常の表示・スクリーンショット・連番出力のすべてに同じく効く。

| トグル | 対象 |
|---|---|
| 背景 | ゲームの背景オブジェクトの配下。背景ウィンドウで複製した背景モデルも含む |
| モデル | モデル配置で置いたモデル |
| PNG | PNG 配置で置いた画像 |

- SceneView とサブカメラには影響しない。SceneView は自分のツールバーのトグルに従う
- プリセット・タイムラインのサムネイル撮影だけは非表示を無視して、全部写す（一覧で見分けるための画像なので）
- 隠した部分は背景色になる。隠したものは影も落とさない
- 状態は保存しない。エディタを有効にするたびに全部表示へ戻る。ツールバーはマウスを乗せないと見えないので、隠したまま忘れるのを防ぐ
- 透過 PNG にするときは、今までどおり背景色のアルファを下げる。黒背景と白背景で 2 回描いて差分を取る既存の撮影を使う
- フォグ・ブルーム・ヴィネットが有効だと、透過の輪郭や背景部分が崩れる（既存の制約。今回は対処しない）

### 4. GameView のマウスオーバーツールバー

GameView ウィンドウの左上（ヘッダーの直下）に、SceneView と同じ半透明の帯でツールバーを置く。マウスが GameView の上にあるときだけ表示する。

| 項目 | 動作 |
|---|---|
| 撮影（カメラのアイコン） | スクリーンショットを撮る。メニューバーの撮影と同じ |
| 比率（コンボ） | 2 節の比率を切り替える |
| 背景 / モデル / PNG（トグル） | 3 節の表示・非表示。ON が表示 |

- 表示するのは、マウスが GameView の上にあって他のウィンドウに覆われていないときと、比率コンボの選択肢を開いている間
- ツールバーの帯の上はシーン操作の対象外。ボタンを押した同じクリックで、カメラが回ったりメイドが選ばれたりしない
- ツールバーは撮影結果に写らない
- 最大化中とウィンドウ一時非表示中は GameView ウィンドウが無いので、ツールバーも出ない
- アイコンを 2 つ足す（撮影: カメラ、PNG: 角を折った画像カード）。背景とモデルは SceneView と同じアイコン
- ツールバーの部品は SceneView と共有する。SceneView のツールバーの見た目と動作は変わらない

### 5. 肘・膝のロール

肘・膝の白丸を `Ctrl` を押しながらドラッグすると、前腕・すねを骨の軸まわりに回す。

- 対象は左右の肘（前腕）と左右の膝（すね）の白丸。胸・肩・手首・足首の点は変えない
- モードは掴んだ時点で決まる。途中で `Ctrl` を離しても切り替わらない（既存の IK 固定・ひねりと同じ）
- 回転角 = 横方向のドラッグ量 (px) ÷ 1.5（度）。手の甲・上体の `Ctrl` ひねりと同じ感度
- 手首・足首の位置は動かず、手首・足首から先は一緒に回る
- `Ctrl` なしで肘・膝をドラッグしたときは、従来どおり IK で動く。今は肘・膝の白丸で `Ctrl` を使っていないので、ほかの操作とはぶつからない
- 「肩から手首の軸まわりに肘を振る（手首は固定）」は今回は作らない
- Undo 1 回で戻る（履歴名「ロール: <点名>」）。クリックで Inspector を開く・ダブルクリックで IK 固定を切り替える操作は従来どおり
- 前腕の軸はゲーム側のひねり処理からローカル X と確認済み。すねの軸は実装の最初に実機で確認する
- 手首・足首を IK 固定していても、ロールは固定に巻き戻されない想定 (固定は手首の位置だけを合わせ、軸まわりのひねりは作り直さないため)。実機で確認する
- 保存形式と設定は変わらない

## 仕様 (#6〜#14)

### 6. 表情ウィンドウのシェイプキータブ

表情ウィンドウに「シェイプキー」タブを足し、顔 (Face スロット) のシェイプキーを編集できるようにする。中身はシェイプキーウィンドウのメイドタブと同じ操作 (タグ一覧・検索・スライダー・更新ボタン)。

- タブの並びは 目 / 眉 / 口 / オプション / 視線 / シェイプキー / プリセット。タブの選択は保存しない
- スロットは顔固定。行の描画は既存の `MaidShapeKeyRowDrawer` を使い、履歴・タイムライン記録も既存のシェイプキーの仕組みに乗る
- スロット・タグ・検索の処理は、シェイプキーウィンドウから共有クラス (`MaidShapeKeyListView`) へ切り出して両方で使う。シェイプキーウィンドウの挙動は変えない
- このタブを開いている間、タイムラインの対象レイヤーはシェイプキーレイヤー (`メイドシェイプ`)。他のタブは従来どおり表情レイヤー
- 表情モーフは一覧から除外する。対象は、表情レイヤーの記録対象と目・眉・口・オプションタブの定義を合わせた名前と、CRC 顔のサフィックス付きの名前 (`eyeclose1_normal` など)。同じ値を表情レイヤーとシェイプキーレイヤーで奪い合わないため
- 強制上書きが OFF の間は、ゲームが毎フレーム顔の値を消すので編集が効かない。スライダーを触ったら強制上書きを ON にする。この切り替えは表情の履歴として別に積むので、Undo は 2 回 (1 回目でシェイプキー、2 回目で強制上書き) で戻る
- シーンプリセットの任意シェイプキー保存も同じ除外判定に揃える。今は CRC 顔のサフィックス付き表情モーフが除外されずに保存される既存の穴がある
- 既知の制約: シェイプキーウィンドウのメイドタブは、従来どおり顔の全シェイプキーを出す。表情モーフの除外を保証するのは新しいタブだけ (ドキュメントに書く)
- 保存形式は変わらない

### 7・13. マテリアルのテクスチャ差し替え (toon・テクスチャ・影の濃さ)

マテリアル編集ウィンドウで、シェーダーに加えてテクスチャも差し替えられるようにする。影の濃さ・影の ON/OFF は toon テクスチャの差し替えで表す (ゲーム自身も肌の影の濃さを toon テクスチャの差し替えで変えている)。

| 対象プロパティ | 参照フォルダ |
|---|---|
| `_ToonRamp` / `_ShadowRateToon` / `_OutlineToonRamp` | `UnityInjector\Config\SceneEditor\Toon\` |
| `_MainTex` / `_ShadowTex` | `UnityInjector\Config\SceneEditor\Texture\` |

- 選べるのは上の専用フォルダ内のファイルだけ (`.png` と `.tex`)。ゲームの arc・Mod 内のテクスチャは選択肢に出さない
- 保存するのは `Config\SceneEditor` からの相対パス (例: `Toon/0_影なし.png`)。フォルダごと渡せば他の環境でも同じ見た目になる。絶対パス・`..`・`:` を含むもの、拡張子違い、プロパティの参照フォルダ外を指すものは、保存時も読込時も捨てる
- サンプルの toon を 4 枚同梱する (`0_影なし` / `1_影薄め` / `2_影標準` / `3_影濃いめ`、256×16 のグレースケール)。実機の toon の形に合わせてスクリプトで自作し、ゲームのテクスチャは再配布しない
- `.tex` はゲームの形式 (版 1000〜1011) を SE 側で解析する (MTEUtils は変えない)
- toon 系は wrap を Clamp に固定する。それ以外は元テクスチャの wrap・filter を引き継ぐ
- 差し替え前のテクスチャを控え、元へ戻せる。読み込んだテクスチャは差し替え・元に戻す・シーン遷移で破棄する。共有キャッシュは持たず、マテリアルごとに読み込む
- ゲーム側が `_MainTex` を作り直した場合 (パーツ色の変更など) は、こちらの差し替えを外す
- 着替えなどでマテリアルが作り直されたら、そのエントリを保留へ戻し、同じアイテムを着直したときに再適用する。**シェーダーだけのエントリにも効くので、従来の「着替えると変更が消える」から挙動が変わる**。別のアイテムへ着替えた場合、エントリは保留のままタイムラインに残る
- 保留の再試行はタイムラインの仕組みで行うので、タイムラインを読み込んでいない間は再適用されない
- 泡スキン (ゲームが作成時に体の toon を 1 回だけ写す) への追従は範囲外
- 保存: タイムラインは `<MaterialShaders>` の各エントリに子要素 `<Texture prop="_ToonRamp" file="Toon/0_影なし.png"/>` を足す。シェーダーを変えていないエントリは `<Shader>` を書かない。シーンプリセットは v37 のまま `ScenePresetMaterial` に `<texture prop file>` を足し、Undo・コピー / ペースト・初期化にも含める。キーフレームは持たない
- 旧 SE はシェーダーが空のエントリを読まず、MTE は `<MaterialShaders>` ごと読み飛ばすので、どちらでも壊れない。ただし旧版で保存し直すとテクスチャ指定は消える
- ファイルが見つからないエントリは指定だけ残し (「見つかりません」と表示)、保存し直しても消さない
- 影を「落とす」側の ON/OFF (Renderer の影キャスト) は今回は作らない。受ける影は、白い `_ShadowRateToon` で消せる

### 8. PNG・モデルをタイムラインごと複製

- モデル
  - 既存の「複製」ボタンを使う
  - 複製先のマテリアルのキー名が `"{new}/{src}/{mat}"` になって効かない既存バグ (`ModelMaterialTimelineLayer.cs:184`) を直す
  - シェーダー・テクスチャの変更も、エントリごと複製先の名前で写す。#7・#13 を後から入れるときは、テクスチャ指定のリストまで複製すること
  - 履歴は既存の「モデルの追加: 表示名」のまま
  - 複製直後 (実体の生成前) に複製先を削除して、シェーダー変更のエントリが残るなら、削除経路で消す
- PNG
  - `DuplicatePng` を足す。画像・位置・色・明るさ・彩度・表示タイプ・デカール設定・ブレンドなどの全設定を写す
  - 「複製」ボタンは PNG の Inspector と、配置済みタブのタイル一覧の上の操作行「選択中を複製」に置く。タイルごとのボタンは共有部品 (MTEUtils) の変更が要るので作らない。配置済みが 0 枚なら操作行を出さない
  - 複製した PNG は一覧の末尾に並ぶ
  - タイムライン編集中は、元のキーを新しい名前へ写してから追加する (0F の自動登録より前なので、写した 0F は上書きされない)。履歴は「PNGの複製: 名前」1 件
  - タイムライン未読込のときは、シーン履歴に「PNGの複製」を 1 件積む
- 既存の問題も直す
  - タイムライン読込時に PNG の番号を振り直すため、欠番のある XML で一部のキーが孤立する → 読込時は XML の番号を保つ
  - PNG の追加・複製を Undo しても実体が残る → Undo/Redo の再構築時だけ、余った実体を消す。新規作成・ファイル読込では、シーンに置いた PNG を消さない
- 既知の制限: Redo で PNG を作り直すとビルボードは既定 (ON) に戻る (削除の Undo にもある既存の制限)
- 保存形式は変わらない (既存の名前・番号の規則に乗る)

### 9. Hierarchy の配置物ビュー

既存の Hierarchy ウィンドウに、タブ「配置物」「GameObject」の表示切り替えを足す。

- 選んだ表示は保存し、既定は「配置物」(既存ユーザーも次回から配置物で開く)
- カテゴリ: メイド / モデル / 背景 (背景モデルの木) / PNG / ライト / サブカメラ。空のカテゴリは出さず、見出しに件数を付ける
- メインライトは出さない (ライトウィンドウと同じ方針)。背景モデルの複製も出さない (背景ウィンドウの木と同じ)
- メイドにアタッチしたモデルは、付け先メイドの子として表示する。判定はタイムラインのキー値ではなく、実際の親子関係で行う
- 行クリックで選択、ダブルクリックで SceneView のフォーカス。SceneView などで選んだものは一覧で強調し、祖先を展開してスクロールする。選んだもの自体が一覧に無いときは、最も近い配置物の祖先を使う
- 検索欄は表示ごとに別の入力として扱う (切り替えで入力中の文字が残らない)
- 今回は表示と選択の連動まで。表示の切り替え・右クリックの複製や削除・ドラッグでの付け替えは後から足す
- 一覧は既存の 0.5 秒ごとの収集で変化を検知したときだけ組み直す (毎フレーム組み直さない)
- 保存形式に影響なし

### 10. 首の白丸

首 (`Bip01 Neck`) に白丸のドラッグ点を足し、頭と首で回すボーンを分ける。

- 今の頭の白丸は、実際には首を回している。これを頭 (`Bip01 Head`) を回すように変え、首の白丸が首を回す
- 操作は頭と同じ (ドラッグで傾け、`Ctrl` で鉛直軸まわりの回転)。クリックでそのボーンを Inspector に出す
- 瞳の操作 (`Alt` + `Ctrl`) は頭の点だけに残す。首の点は `Alt` 中は掴めない
- 首の点は首と頭のボーン位置の中点に置く (首の付け根だと上体・肩の点に近いため)。回転の支点は首ボーンの原点のまま。点どうしの間隔は実機で測り、近すぎれば位置の比率を調整する
- 頭の点で回すときは、顔がカメラを追う動き (`HeadToCam`) を止めて、頭が引き戻されないようにする (頭ギズモと同じ処理)
- 履歴名は、頭が「顔向き操作」、首が「首操作」、瞳が従来どおり「目線操作」
- 既知の制約: タイムラインで「メイド目線」が顔を向ける系 (`顔を向ける` など) のとき、頭のキーは記録されない (頭ギズモと同じ既存の制約)。従来の頭の白丸は首を回していたので起きなかった退行なので、この場合は首の点を使うようドキュメントで案内する
- 頭の点の挙動が変わるので、変更履歴とドキュメントの操作表に書く

### 11. ギズモの座標系にカメラ方向

ギズモの座標系を ローカル / ワールド / カメラ の 3 値にする。

- カメラ: 軸はそのギズモを見ているカメラの右・上・前 (SceneView と GameView で別)
- 移動: 画面に沿った右・上の矢印と、画面と平行な面だけを出す。奥行きの矢印は出さない (奥行きはローカル / ワールドで動かす)
- 回転: 画面に正対する白い外周リングで、視線まわりに回す。右・上の軸は、マウスの移動量を角度に換える方式 (トラックボール) で回す。外周リングはカメラ座標系のときだけ出し、ローカル / ワールドの見た目は変えない
- 拡縮ツールはカメラでは意味が無いのでローカルで動かす。ボーン回転ギズモは従来どおりローカル固定
- Inspector の位置・回転の数値欄は、カメラのときワールドとして表示する
- 切り替えは既存の地球アイコンのボタンを ローカル → ワールド → カメラ の巡回にする (Inspector と SceneView ツールバー)。カメラのアイコンは既存のものを流用する
- ギズモ本体は MTEUtils サブモジュールを変更する。サブモジュール内で先にコミットし、SceneEditor 側の参照を進める
- 外部プラグイン連携は `useLocalSpace` が bool 型であることをリフレクションで要求しているので、bool のプロパティは互換用に残し、3 値の設定を別に足す。カメラのとき bool は false (ワールド) を返す
- ModItemExplorer は 3 値に対応させない。SceneEditor でカメラを選んでも、ModItemExplorer 側ではワールドとして見えるだけで壊れない
- 設定は既存の `gizmoUseLocalSpace` を残して `gizmoSpace` を足す。読み込み時に両者が食い違っていたら bool 側を正とし、これで旧設定からの移行も兼ねる

### 12. 表情の強制上書きを既定 ON

- 新しく呼び出したメイドのロードが終わったときに、強制上書きを ON にする。その時点の表情を固め、まばたきを止めてから ON にするので、無表情や半目で固まらない
- すでに配置済みのメイドを呼び直す場合は、ユーザーの設定を保つ
- シーンプリセットの保留適用はこの後に走るので、旧データのプリセット (強制上書き OFF) はプリセットどおり OFF になる
- シーンプリセット・表情プリセットの既定値 (旧データの読み込み時) は変えない。旧プリセットの見た目が変わるため
- タイムラインは既に既定 ON なので変えない
- ON にするとまばたきが止まる。変更履歴に書く (CHANGELOG はリリース準備で書く)

### 14. CM3D2 の背景

- ゲームの互換モードが有効なら、CM3D2 側の `phot_bg_list.nei` を読んで背景一覧に足す
- 絞り込みはゲームとほぼ同じ (有効 ID リストと必要パック)。ただしゲームは有効 ID リストが読めないと全行を弾くが、こちらは空なら絞り込まない
- 2.5 の一覧と prefab 名が重なるものは出さない。大文字小文字は区別しない (`SMRoom2` と `smroom2` など。区別すると重複を 2 件しか除けない)
- カテゴリ名は「CM3D2:」+ カテゴリ (例: `CM3D2:夜伽` / `CM3D2:一般`)。カテゴリの一覧でも「すべて」でも、2.5 の背景の後ろに並ぶ
- 実機では 55 件のうち重複 6 件を除いた 49 件が加わる
- 適用・保存は prefab 名で行う。プリセットには `bgId` を入れず `bgPrefabName` で保存するので、保存側のコードは変えない。旧版でもゲーム側の読み込み経路で復元できる
- 背景ウィンドウを開く前にプリセットで CM3D2 の背景を復元しても、Inspector に表示名が出る
- CM3D2 が未導入の環境では何も足さない
- 2.0 も同じ API を持つことをコードで確認済み (2.0 と 2.5 で作り分けない)。2.0 の実機では未検証
- 参考実装は MeidoPhotoStudio の `BackgroundRepository.cs:127-151`
