# 背景のみライトでキャラの影を落とす 設計

## 目的

照射対象を「背景のみ」にした追加ライトでも、キャラ（メイド・男）の影を背景へ落とせるようにする。

今は「背景のみ」にすると、キャラはそのライトに照らされなくなるのと同時に、そのライトの影も落とさなくなる。キャラを照らさずに床へ影だけ落とす、という照明が組めない。

成功条件:

- 「背景のみ」で影ありの追加ライトが、キャラの影を背景へ落とす
- キャラ自身は、そのライトに引き続き照らされない
- 影を落とすかどうかをライトごとに切り替えられる
- 着替え・メイドの追加と削除・非表示に追従し、消えたキャラの影が残らない
- 既存のシーン（XML・シーンプリセット）を読み込んだときの見た目は変わらない

## 範囲

- 含めるもの
  - 対象のライト: SceneEditor の追加ライト（index > 0）。照射対象が「背景のみ」で、影の種類が「なし」以外のもの
  - 影を落とすキャラ: メイドと男。Renderer のレイヤーが `LightTarget.CharacterMask`（Charactor / Face / Man）に入っているもの
  - ライト定義に「キャラの影」設定を追加する。Inspector・タイムライン XML・シーンプリセット・ライトのコピー/貼り付け・Undo に載せる
- 含めないもの（必要になったら別途設計する）
  - メインライト（index 0）。ゲーム側の恒久オブジェクトで、照射対象も変えていないため
  - 表示レイヤーを Charactor などにしたモデル（`<ModelLayer>`）。モデルは追加ライトの照射対象の仕組みと別に動くため
  - キャラへの影の落ち方の変更。「背景のみ」のライトはキャラを照らさないので、キャラが影を受けることもない
  - 撮影モード（既存の方針どおり非対応）

## 実機調査で分かった前提

COM3D2.5 のライブステージで devbridge から調べた結果（2026-10-05）。比較には、平行光源の向きと強さを一時的に変え、影を受ける仮の床を足元に置いた。値は、足元から伸びる影の帯の平均輝度（小さいほど影が濃い）。

| 状態 | 影の帯の明るさ |
|---|---|
| 通常（ライトがキャラを含む） | 68.9 |
| ライトの `cullingMask` から Charactor を外す | 88.8（影が消える） |
| 上に加え、影専用の複製を置く（複製のレイヤーはライトとカメラの両方に入っている） | **68.9（通常と同じ）** |
| 複製のレイヤーがカメラの `cullingMask` に入っていない（ライトには入っている） | 88.8（影が消える） |
| 複製のレイヤーがライトの `cullingMask` に入っていない（カメラには入っている） | 88.8（影が消える） |

ここから分かること:

- **ライトの `cullingMask` から外したオブジェクトは、そのライトの影も落とさない**（Unity 標準パイプラインの挙動）。照射対象の切り替えだけでは解決できない
- **影専用の複製で影を戻せる**: 元の `SkinnedMeshRenderer` と `sharedMesh`・`bones`・`sharedMaterials` を共有する複製を作り、`ShadowCastingMode.ShadowsOnly` にする
  - ボーンを共有しているので、モーションにそのまま追従する
  - `ShadowsOnly` なので本体は描かれない
- **複製のレイヤーは、カメラとライトの両方の `cullingMask` に入っている必要がある**。逆に言えば、複製用のレイヤーのビットをライトの `cullingMask` に入れるかどうかで、ライトごとに影の有無を切り替えられる
- **複製はメイドの階層の外に置ける**: 専用のルートの下に置いても、影の濃さは同じだった（68.9）
  - メイドの `SkinnedMeshRenderer` は `rootBone` がすべて空だった。複製では `rootBone` に元の Renderer の Transform を指定し、`localBounds` を写す。こうしないと描画範囲の基準が複製のルートになってずれる
- **ブレンドシェイプは使われていない**: メイドの全 `SkinnedMeshRenderer` の `blendShapeCount` は 0 だった。体型や表情の変形はメッシュを直接書き換える方式（TMorph）なので、`sharedMesh` を共有すれば複製も追従する
- **`ShadowCastingMode.Off` の部位がある**: 顔（`Face7`）は元から影を落とさない。この部位は複製しない

## 方式

### 複製用レイヤー

- 名前の付いていないレイヤー（`LayerMask.LayerToName` が空）のうち、メインカメラの `cullingMask` に入っていて、`LightTarget.CharacterMask` に入っていないものを、起動後の初回に 1 つ選ぶ。番号は固定で埋め込まない
  - 調査時の環境では 3・6・7 が該当した
  - SceneEditor・PostEffects ともに、名前のないレイヤーは使っていない
- 該当するレイヤーが無いときは機能を無効にし、エラーログを 1 回だけ出す。UI の「キャラの影」も操作できないようにする
- 以降、このレイヤーのビットを「影ビット」と呼ぶ

### 設定の持ち方（`cullingMask` の影ビット）

照射対象と同じく、実行中の真の値はライトの `cullingMask` に持たせる（照射対象も `LightTarget.FromCullingMask` で `cullingMask` から逆引きしている）。

| 照射対象 | キャラの影 OFF | キャラの影 ON |
|---|---|---|
| 全て | `~影ビット` | `-1` |
| キャラのみ | `CharacterMask` | `CharacterMask \| 影ビット` |
| 背景のみ | `~CharacterMask & ~影ビット` | `~CharacterMask` |

- **照射対象が「背景のみ」以外のときも影ビットを残す**: 照射対象はタイムラインのキーで切り替わる。影ビットを消すと、「背景のみ → 全て → 背景のみ」と切り替えたときに設定が失われるため
  - 「全て」「キャラのみ」のライトに影ビットが入っていても、複製はキャラ本体と同じ位置に同じ形の影を落とすだけなので、見た目は変わらない。増えるのは影の描画コストだけで、それも複製が存在するときに限られる
- `LightTarget` を次のように拡張する
  - `ToCullingMask(mode, characterShadow)`: 上の表のとおりに組み立てる
  - `FromCullingMask(mask)`: 影ビットを取り除いてから、今と同じ判定をする
  - `HasCharacterShadow(mask)`: 影ビットが立っているか
  - テスト用に、`characterMask` と影ビットを注入できる版も用意する（既存の `ToCullingMask(mode, characterMask)` と同じ作法）
- 照射対象を `cullingMask` へ書き込んでいる箇所は、すべて今の影ビットを引き継ぐようにする
  - `LightTimelineLayer`（キーの適用、150 行付近）
  - `LightRowDrawer`（照射対象のコンボ、407 行付近）
  - `LightClipboard`（貼り付け、101 行付近）
  - `LightSnapshot`（Undo の復元、153 行付近）

### 影専用の複製の管理

新しいマネージャ（例: `CharacterShadowProxyManager`）を作る。

- **複製を持つ条件**: 有効な追加ライトのうち、照射対象が「背景のみ」・影が「なし」以外・影ビットありのものが 1 つでもあるとき。条件を満たすライトが無くなったら、複製をすべて破棄する。判定は毎フレーム行う（ライトは数灯なので軽い）
- **複製する Renderer**: メイドと男の配下で、次をすべて満たすもの
  - レイヤーが `LightTarget.CharacterMask` に入っている
  - `shadowCastingMode` が Off ではない
  - `SkinnedMeshRenderer` である。`MeshRenderer` は調査時のメイドには無かったが、見つかった場合は複製の Transform を毎フレーム元に合わせる
- **複製の作り方**
  - 専用のルート（`HideAndDontSave`）の下に置く。メイドの階層には入れない。ゲームや他の機能が `GetComponentsInChildren<Renderer>` で集める対象に混ざらないようにするため
  - 共有するもの: `sharedMesh`、`bones`、`sharedMaterials`（アルファテストの切り抜きを影に反映させるため）
  - `rootBone` には元の Renderer の Transform を指定し、`localBounds` を写す
  - `shadowCastingMode = ShadowsOnly`、`receiveShadows = false`
  - レイヤーは複製用レイヤー
  - ブレンドシェイプを持つメッシュがあれば、重みを毎フレーム写す（調査時は 0 個だった）
- **追従**: 次のときに作り直す。作り直しの判定は `MaidGravityController` の作法にならう
  - メイド・男の追加と削除
  - 着替えの完了（`IsAllProcPropBusy` が true から false へ変わったとき）
  - 元の Renderer の破棄、`sharedMesh`・`sharedMaterials` の参照の差し替え（`MaterialShaderManager` のシェーダー変更を含む）
  - 取りこぼし対策として、`ViewCullingFilter` と同じく一定フレームごとに作り直す
- **表示の追従**: カメラの描画ごとに、元が描かれないなら複製も影を落とさないようにする。次のどれかに当たれば、そのカメラの描画中は複製を無効にし、描画後に戻す
  - 元の Renderer が無効、または GameObject が非アクティブ
  - 元のレイヤーが、そのカメラの `cullingMask` に入っていない（例: PostEffects の「メイド非表示」は Charactor / Face をカメラから外す。調査時のメインカメラは Man レイヤーも外していた）
  - `ViewCullingFilter` がメイドを隠している（GameView・SceneView の「メイド非表示」）
  - 影の計算はカメラごとに行われるため、この切り替えはカメラ単位で効く
- `MaidVisibilityController` の非表示（メイドを遠くへ退避させる方式）は、ボーンごと動くので対応不要

## UI

`LightRowDrawer` の影の行（`DrawShadowTypeRow`）の下に、トグル「キャラの影」を追加する。

- 表示する条件: 影が「なし」以外で、今の照射対象が「背景のみ」のとき。ほかの照射対象では意味が無いので出さない
- 変更は `RecordLightEdit` で Undo に記録する（ほかの行と同じ）
- 複製用レイヤーが確保できなかったときは、操作できない状態で表示し、理由をツールチップで示す

## 保存と互換性

| 保存先 | 追加するもの | 既定値と書き出し |
|---|---|---|
| タイムライン XML のライト定義（`TimelineLightXml`） | `<CharacterShadow>`（bool） | 要素が無ければ false。true のときだけ書き出す |
| ライト定義の実行時データ（`TimelineLightData` / `StudioLightStat`） | `characterShadow` | 定義の同期（`StudioLightManager` の 152 行付近・257 行付近・275 行付近）で、影の種類と一緒に `cullingMask` へ反映する |
| シーンプリセットの追加ライト（`ScenePresetAdditionalLight`） | 属性 `characterShadow` | 属性が無ければ false。true のときだけ書き出す。`ScenePresetData.CurrentVersion` を 38 から 39 へ上げる |
| ライトのコピー/貼り付け（`LightClipboard`） | `characterShadow` | 貼り付けで影ビットも写す |
| Undo（`LightSnapshot`） | `characterShadow` | 差分の比較（213 行付近）にも含める |

- **新しく作る追加ライトの既定値は ON**。このトグルは「背景のみ・影あり」のときしか効かないので、ほかの設定の見た目は変わらない
- **既存データは OFF として読む**。今まで「背景のみ」のライトではキャラの影が出ていなかったので、読み込んだシーンの見た目を変えない
- キーフレームは追加しない。輪郭（cookie）の画像や影の種類と同じく、ライト定義の値として持つ。タイムライン XML の version は上げない
- MTE は `<CharacterShadow>` を読み飛ばす。MTE には照射対象の仕組みが無いので、ほかの影響は無い。旧 SE も要素を読み飛ばし、今までどおりキャラの影なしで表示する
- 実装後、親リポジトリの `CLAUDE.md`「タイムライン XML の互換方向」へ 1 項目追記する

## 性能

- 複製の数だけスキニングの計算が増える。調査時のメイド 1 人では 7 個だった
- 複製は影の描画（シャドウマップ）にだけ加わる。カメラの通常の描画・深度テクスチャには入らない
- 条件を満たすライトが無いときは複製を持たないので、この機能を使わない限りコストは増えない

## 要確認事項

実装計画を立てる前に、ユーザーの判断や実機での確認が必要なもの。

1. **新規ライトの既定値**: ON（推奨）か OFF か
2. **トグルの表示条件**: 照射対象が「背景のみ」のときだけ出す（推奨）か、影ありなら常に出すか。照射対象はキーで切り替わるので、今のフレームの値で表示が変わる
3. **呼び出し順の実機確認**: PostEffects の `MaidHideEffect` は自分の `OnPreCull` でカメラの `cullingMask` を書き換える。複製の表示判定をどのタイミングで行えばこの書き換えの後に読めるかを、実機で確かめる（`Camera.onPreCull` と、各コンポーネントの `OnPreCull` の順序）。`ViewCullingFilter` との順序も同様に確かめる
4. **男のメッシュ構成**: 調査は女性メイドだけで行った。男の Renderer の種類・`rootBone`・`shadowCastingMode` を実機で確かめる

## 検証手順

1. ライブステージなどで、追加ライト（平行光源）を作る。照射対象を「背景のみ」、影を「ソフト」にする
2. キャラの影が床に落ちること、キャラ自身はそのライトに照らされないことを確かめる
3. 「キャラの影」を OFF にすると影が消え、ON に戻すと出ることを確かめる
4. 照射対象を「全て」→「背景のみ」とキーで切り替えても、設定が保たれることを確かめる
5. 着替え・メイドの追加と削除・GameView の「メイド非表示」・男の非表示で、影が追従するか消えることを確かめる
6. XML とシーンプリセットに保存して読み直し、設定が戻ることを確かめる。既存の XML・プリセットを読み込んで、見た目が変わらないことを確かめる
7. 条件を満たすライトを消したとき、複製がすべて破棄されることを確かめる（devbridge で専用ルートの子の数を見る）
