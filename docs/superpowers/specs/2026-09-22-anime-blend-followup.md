## 新しく決めた仕様: 編集モード中のベースモーション差し替え

計画には無かった論点。検討の結果、次の 2 点を決めた (手編集の扱いは従来どおり破棄)。

- **編集モード中は差し替えても再生を始めない**。先頭フレームで停止したまま当てる。
  編集モードは「止めてポーズを触る」状態が前提のため。編集モード外は従来どおり再生する
- **差し替えてもブレンド層は残す**。保持するのは層の内容 (アニメ名・重み・速度) で、
  有効 / 無効は既存の `ShouldKeepLayersWhileStopped` に従う

実装は 2 段構え。どちらか片方だけでは層が残らない。

1. `MaidCache.ResetAnm(keepLayers)` — `OnAnmChanged` (ベースのアニメ名変更) からは層を捨てず、
   死んだ `AnimationState` だけ落とす。メイド解除等からの全消去は既定 `false` のまま
2. `MaidAnimationBlendController.SyncFromAnimation` — 記録済みの `anmName` で段を引き当て直す。
   `enabled` を条件にすると、編集モード中に意図的に無効化した層を空と誤判定して捨ててしまう

## 不具合と原因

### 編集モード終了時の再入 (`d7dd2d4`)

編集モードを抜ける処理が自分自身を打ち消していた。流れは次のとおり。

1. `isEditMode` の setter が `_isEditMode = false` を代入する
2. 同じ setter が anm 化を呼ぶ
3. anm 化の履歴登録が `AutoEditMode.Enter()` を経由する
4. `Enter()` が `isEditMode = true` を書き戻す
5. 結果、トグルを OFF にしても内部は ON のまま残る

遷移中フラグ `_isChangingEditMode` で再入を弾いた。ただしこれだけでは
`AutoEditMode.Enter()` の他の副作用が残り、後述の `9e16270` で追加対応した。

### 停止中の `Restore` が層を無効のまま残す (`d7dd2d4`)

`Restore` は `info.state.enabled = basePlaying` とするため、停止中の復元では層が必ず無効になる。
`SampleStopped` はベースしか触らないので、シーンプリセット復元でも undo/redo でも
ブレンドが見えなくなっていた。層を見せる条件なら `KeepLayersAfterStop` してからサンプルする。

### anm 化したポーズをエディット系と誤判定 (`63debb1`)

`IsScriptMotionApplied` が「ファイル情報の無い適用記録＝エディット系」と推定していた。
anm 化が作る記録は `displayName` だけなので誤判定していた。その結果、`適用先` タブが毎フレーム
ベースへ戻され、「エディット系はブレンド非対応」という誤った表示が出る。適用記録に `isResidentPose` を足して区別する。

**シーンプリセット復元の記録も同じ形だったため、以前から同じ誤判定をしていた。**

### anm 化が編集モードを抜ける操作を打ち消す (`9e16270`)

再入ガードは `isEditMode` の状態破壊は止めた。しかし `AutoEditMode.Enter()` 自体の実行は止めていない。
そのため `SceneEditorHack.isPoseEditing` が立ち直り、停止していたベースの再生まで再開してしまう。
結果、固めた編集ポーズが元モーションで上書きされる。

自動移行をしない `HistoryManager.BeforeEditWhileLeavingEditMode` を追加し、anm 化はそちらを使う。

### ブレンド込みボーンがキー化される (`28f1854`)

`適用先` がレイヤーの間はボーンを触れないが、層は有効なままなので実ボーンにブレンドが乗っている。
キー登録は Category モードでメイド系の全レイヤーを対象にするため、`Enter` を押すと
**触れないはずのボーン**がブレンド込みで「メイドアニメ」(`MotionTimelineLayer`) へ焼き込まれていた。

`ShouldSkipBoneKeyFrame` を足し、ボーン由来のレイヤー
(`MotionTimelineLayer` / `MoveTimelineLayer`) を登録対象から外す。
「メイドアニメブレンド」自身は層の値を記録するので対象外。

### 適用に失敗したモーションで停止・記録が進む (`bbae627`)

ゲーム側の `PhotoMotionData.Apply` は `maid.IsBusy` (着替え等の `AllProcProp` 中) だと何もせず戻る。
`PhotoMotionUtils.Apply` はこれを見ずに `Discard` と `RecordAppliedMotion` まで進め、
当たっていないモーションを記録していた。`bool` を返すようにして `IsBusy` を先に弾く。

## 教訓

- **6 件中 4 件はユニットテストとコードレビューをすり抜け、実機でしか出なかった**
  (`63debb1` / `9e16270` / `6252e09` / `28f1854`)。層の状態遷移
  (再生 / 停止 / 編集モード / 差し替え) の組み合わせが Unity のランタイム挙動に依存するため
- レイヤーの表示名は紛らわしい。**「メイドアニメ」= `MotionTimelineLayer`**、
  **「メイドアニメブレンド」= `AnimationTimelineLayer`**。調査中に取り違えて誤った分析をした
- 非ループの .anm を層に載せると再生し終わって Unity が自動で無効化する。
  検証でこれを不具合と誤認したので、層の挙動を見るときはループするアニメを使う
