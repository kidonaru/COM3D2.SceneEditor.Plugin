# Blender のメッシュでサイリウムを配置する

SceneEditor のサイリウムエリアに、任意の配置点を使う機能を追加した。Blender で円形・扇形・通路を空けた面などを作り、その面の範囲に席を生成できる。段差も配置点の高さとして保持する。各席の本数・色・揺れ・アニメーションは従来のタイムライン設定を使う。

## 今回の確認用データ

リポジトリの `output/cyalume-import/` に以下を出力した。

| ファイル | 内容 |
|---|---|
| `仮装狂騒曲 篠澤広123_円形配置.xml` | 指定されたタイムラインに配置点のみ追加した確認用データ |
| `live_stage_psyllium_placement.blend` | 元のステージに編集用の配置点メッシュを追加した別名保存ファイル |
| `placement_area0.xml` ～ `placement_area3.xml` | エリア単位で読み込み直せる配置ファイル |
| `reference-report.json` | 配置点数と座標変換の記録 |
| `COM3D2.SceneEditor.Plugin.dll` | 今回の改修を含む COM3D2.5 向け DLL |

Blender の観客シルエットから 3,559 席を抽出し、既存の 4 エリアへ 924 / 926 / 856 / 853 席ずつ振り分けた。ステージ周囲と 9 段の客席を含み、正面通路も元データのまま空いている。1 席は左右の手の基準点であり、サイリウムの本数とは異なる。

配置の変換にはモデル書き出し倍率 `0.2` と指定 XML のステージ倍率 `3.2` を合わせた `0.64`、移動 `(0, -2.459999, 0)` を使用した。手元の高さは Blender の客席床から `1.1`。各席の向きは既存タイムラインと同じで、色・本数・振り付けのキーは変更していない。

元の `.blend` と指定のタイムライン XML は上書きしていない。確認用 XML は改修後の DLL が必要。旧 DLL は配置点を認識せず矩形配置になる。

## Blender で範囲メッシュを作る

1. `tools/blender/export_psyllium_placement.py` を Blender のテキストエディターで開き、スクリプトを実行する。ファイル → エクスポートに「SceneEditor サイリウム配置 (.xml)」が追加される。通常のアドオンとしてインストールしてもよい。
2. 配置したい範囲を **面のあるメッシュ** で作る。円周状なら中央を開けたリング面、扇形なら不要な面を削除したリングを使う。ステージと通路の部分には面を作らない。
3. オブジェクトモードで範囲メッシュだけを選択し、配置 XML をエクスポートする。
4. 「面の範囲内に配置」を選び、席間隔・手元の高さ・変換倍率・移動を指定する。

面は上向きの法線が必要。Blender の上方から見て面のある位置だけに、等間隔の席を作る。モディファイアとオブジェクトの移動・回転・スケールを反映する。円形の範囲内も席自体は格子状に並ぶ。

**円周に沿う列を正確に作る場合**は「頂点を配置点にする」を使う。円メッシュの頂点を席にし、複製して半径や高さを変えれば同心円状の客席を作れる。不要な頂点を削除すれば通路も空けられる。確認用 `.blend` の `SceneEditor | サイリウム配置点` コレクションはこの方式で、各メッシュを 1 つずつ書き出す。頂点は床の高さなので手元の高さ `1.1` を設定する。

1 エリアは最大 5,000 席。広い範囲は複数の配置ファイルに分け、別々のエリアへ読み込む。同じメッシュ内で上下に面が重なる場合、面からの配置では最上面を使う。上下階を両方使う場合はメッシュを分ける。

## SceneEditor で読み込む

1. 改修した DLL を導入してゲームを再起動し、タイムラインを開く。
2. ライブ演出 → サイリウム → エリアで対象を選ぶ。
3. ポーズ編集モードで「配置 XML を読み込む」を押す。
4. タイムラインを保存する。

外部配置 XML はコントローラー座標で読み込み、現在のエリアの位置・Y 角度を差し引いて保持する。読み込み時はエリアの X/Z 角度を 0 にする。コントローラーに変換がある場合は、書き出し側の倍率・移動をコントローラー基準へ合わせる。今回のコントローラーは位置・角度とも 0。

読込後はエリア／コントローラーの移動・回転で配置全体を動かせる。SX/SY・席幅・列幅は矩形配置用のため、メッシュ配置時には使わない。密度や範囲は Blender で編集し、再書き出し・再読み込みする。「矩形配置に戻す」で従来の方式へ戻せる。

配置点は各キーに繰り返し保存せず、タイムライン XML の `Psylliums/Psyllium/Placement` にまとめて保存する。元の配置ファイルがなくても再生できる。エリアコピーでは配置も複製するが、「位置/角度/サイズ/配置を反映しない」がオンならコピー先の配置を保持する。

「中心を向く」を選ぶと席ごとの向きも書き出せる。この場合は既存の動きが各席の向きを基準に回転する。今回の確認データではオフにしている。

中心を向かせた結果が逆向きになる場合は、書き出し時の「向き／中心向き補正（度）」を `180` にする。中心方向の計算は +Z を前方としているため、-Z を前方に作った振り付けにはこの補正が必要。更新した書き出しスクリプトを Blender で再実行してから、配置 XML を再書き出し・再読み込みする。DLL の交換や振り付けのキー編集は不要。エリア全体の Y 角度を変えると席の位置まで回るため、向きだけの修正には使わない。

## 導入と確認状況

COM3D2.5 向け DLL: `source/COM3D2.SceneEditor.Plugin/bin/Debug/COM3D25/COM3D2.SceneEditor.Plugin.dll`

ゲームへは未配置。稼働中のゲームは従来 DLL を読み込んでいるため、改修した配置の実機再生・見た目・処理負荷は未確認。

現在のステージ Prefab には、固定サイリウムの `客席専用 | 0` ～ `3` を使う Renderer が 8 個あり、有効になっていることを読み取り確認した。動くサイリウムだけを表示するには、この固定サイリウム部分を非表示にするか、同部分を除いた Prefab を使う。今回の改修・確認用 XML では背景側の表示設定を変更していない。

以下の自動テストは C# 7 件、Blender 7 件の計 14 件が成功した。

検証内容:

- COM3D2.5 向けビルド。
- 配置 XML の往復、独立コピー、旧 XML の互換性、点数上限、不正座標・角度の拒否。
- エリア回転のキーフレーム変換。
- Blender 5.1.2 でリングの穴、段差、ワールド変換、配列モディファイア、軸変換、重複点除去、再登録。
- 確認用タイムラインの配置要素を除去すると、全データが元 XML と意味的に一致すること。

## 実装上の要点

`PsylliumArea` が配置点を `areaConfig` とは別に保持するため、既存のキー再生による設定置換で配置点が消えない。手の生成とパターン適用は矩形配置と共通。配置がない旧 XML は従来どおり矩形で再生し、再読込では前の配置を消してから復元する。

併せて、従来の `TransformDataPsylliumArea` が設定との相互変換時に角度を転送していなかった点を修正した。エリア回転を保存・復元できる。

Blender API は Context7 で [評価済みメッシュ](https://docs.blender.org/api/current/bpy.types.Depsgraph.html)、[BVHTree](https://docs.blender.org/api/current/mathutils.bvhtree.html)、[エクスポートオペレーター](https://docs.blender.org/api/current/bpy.types.Operator.html) を確認した。
