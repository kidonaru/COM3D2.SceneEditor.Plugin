# タイムライン リリース前 仕様精査（負債候補一覧）

作成日: 2026-09-13
対象: `docs-site/timeline/` 配下の仕様ドキュメント 18 ファイル（タイムライン XML version 34 時点）

リリース後は XML 形式と識別子が事実上固定されるため、**優先度 高 は version 34 を公開する前に対応可否を決める**必要がある。

## 優先度 高: XML 形式・識別子に関わるもの

| # | 仕様 | 問題 | 対応案 |
|---|---|---|---|
| 1 | `メイド衣装` レイヤーだけメイド単位ではなく、タイムラインに 1 本で先頭スロットにしか効かない | 他のメイド系レイヤーと非対称。後からメイド単位へ変えると XML のレイヤー構造が変わりマイグレーションが必要 | メイド単位に揃える |
| 2 | モデルの対応付けが「ファイル名 + 配置順のグループ番号」 | 同じファイルを複数置くと並び替えでキーの割当先がずれる（仕様書自身が認めている） | 配置時に安定 ID を採番して保存し、それで対応付ける |
| 3 | 階段状に切り替えるプリセットが無く、`1フレーム調整`（全体設定）でステップ補間を代替 | 後からキー単位のステップ補間を足すと、既存データが依存する全体設定と二重管理になる | キー単位のステッププリセットを追加し、`1フレーム調整` は互換読込専用へ落とす |
| 4 | ポストエフェクトが区間の代表タンジェントで全項目を一括補間 | 他レイヤーは値ごとにタンジェントを持つ。後で個別化すると XML の持ち方が変わる | 値ごとのタンジェントに揃える |
| 5 | 保存されるが使われない値が残る: `アスペクト比` / `ﾚﾀｰﾎﾞｯｸｽ透過度`、開始・終了オフセット時間とフェード時間、PNG 配置の MTE 固有値（反転、カメラ追従、アタッチ、APNG 等） | 後で実装した瞬間に既存ファイルの見た目が変わる | 実装するか、保存対象から外すかを今決める |
| 6 | 未使用レイヤーが保存時に空レイヤーとして実体化される | 「レイヤーが無いとゲートが出る」仕様と噛み合わない。一度保存して読み直すとゲートは二度と出ず、XML も肥大する | 空レイヤーは保存しない |
| 7 | フレームレート変更でキー位置が再計算されない（仕様書に記載なし。`TimelineSettingWindow` は `frameRate` を差し替えて現在フレームを再適用するだけ） | 30→60 に変えるとアニメが 2 倍速になる | 仕様として明記するか、時間基準でキーを再配置する |
| 8 | テンプレートの保存先が MTE と共用（`Config\MotionTimelineEditor\Template\`） | 両プラグインが同じファイルを上書きし、片方の変更が消える | SceneEditor 専用フォルダへ移し、初回だけ MTE 側から取り込む |

## 優先度 中: 挙動の意味が複雑で説明しづらいもの

| # | 仕様 | 問題 | 対応案 |
|---|---|---|---|
| 9 | `登録`(Enter) の対象が「グリッドに表示中のレイヤー」 | 表示モード（カテゴリ / レイヤー）という表示状態がデータ操作の範囲を決める。`カメラ同期` OFF 時はカメラのキーが打たれない、カメラは自動登録対象外、と 3 ルールが絡む | 登録対象を明示的な概念（レイヤーごとの記録トグル等）に一本化する |
| 10 | `カメラ同期` / `ポスプロ同期` が再生反映と登録可否の両方を兼ねる | 表示制御のトグルがデータ変更にも効く | 再生反映と登録可否を分離する |
| 11 | ライブ演出（ステージライト・レーザー・サイリウム）が操作履歴非対応 | 自動登録も効かず Undo もできない、と例外が二重に生じる | 履歴対応する（両方の但し書きが消える） |
| 12 | Undo の穴: トラックの追加・並べ替え・範囲変更、`最終フレーム` 変更、新規作成・読込直後の最初の操作。タイムライン読込中は通常のシーン操作が履歴に載らない | 利用者からは Undo が壊れて見える | 履歴対象を広げる。シーン操作とタイムライン操作の履歴統合を検討 |
| 13 | 0 フレーム目キー必須が `メイドアニメ` / `メイド表情` / `メイド瞳` / `メイド脱衣` の 4 レイヤーだけ | 保存と .anm 出力をブロックする割に、対象の選び方が説明しづらい | レイヤー作成時に 0 フレームキーを自動で打ち、制約自体を消す |
| 14 | レイヤー削除時の実体の扱いが不統一（`サブカメラ` は実体破棄、`背景色` は地面が残る） | 所有関係が読めない | 方針を統一する |
| 15 | メイド追加後、`操作対象` で選んだ時点で「現在のレイヤー種類」だけ作られる | 増えるレイヤーがそのときの UI 状態に依存する暗黙の副作用 | 追加時に明示的に作るか、何も作らない |
| 16 | `メイド目線` の設定がシーンプリセット側に保存される一方、仕様上は「タイムライン全体の設定」 | 所有者が二つに分かれる | どちらかに寄せる |
| 17 | 補間方式のばらつき: `背景色` は色なのに補間なし（他の色は線形）、`テキスト` の Transform とサブカメラの VP は線形、他はタンジェント、PNG 配置の拡縮は X・Z のみ | 意図的でないものは仕様書を長くするだけ | 揃える |
| 18 | 回転がクォータニオンで、カーブエディタでは表示専用 | 位置は編集でき回転は編集できない非対称 | 許容するなら明記。可能ならオイラー角編集を提供 |

## 優先度 低: UX の不整合（データ互換に影響しない）

| # | 仕様 | 問題 |
|---|---|---|

| 21 | ショートカットが `タイムライン操作` ウィンドウ表示中のみ有効 | ウィンドウの表示状態にキー処理が縛られる |
| 22 | グリッドのズームが設定ファイル編集のみ | UX |
| 23 | タイムラインの削除・リネーム機能が無い。既定アニメ名 `テスト` | UX |
| 24 | `個別設定を初期化` で `最終フレーム` だけ戻らない | 不整合 |
| 25 | `ボイス最大秒数` / `移動範囲` という共通設定がキーの値域を決める | 設定を変えると既存データの表現範囲が変わる |

## 検討結果（2026-09-13 追記）

優先度 高の 8 項目はコード調査のうえ `docs/superpowers/specs/2026-09-13-timeline-release-debt-design.md` で決定した。調査で判明した仕様書との食い違い:

- 5: `アスペクト比` / `ﾚﾀｰﾎﾞｯｸｽ透過度` は `LetterBoxView` が実装済みで、**実機で描画されることを確認した**（2026-09-13。`LetterBoxView` + `LetterBoxLine_0/1` がアクティブで、GameView に黒帯が出る）。仕様書の「反映されません」が誤りだったので削除した。`startOffsetTime` は BGM・動画・CSV 出力で使用中。読み手が無いのは `endOffsetTime` / `startFadeTime` / `endFadeTime` のみ
- 6: 保存処理はレイヤーを作らない。実体化の主経路は `操作対象` メイド切替時の暗黙作成（項目 15 と同根）
- 4: MTE も per-key easing による一括補間で、SE の代表タンジェントはその等価変換。ただし SE では値ごとのタンジェントが既に保存されているため、適用側の書き換えだけで個別補間に移行する（XML 不変）

優先度 中の 9〜18 は `docs/superpowers/specs/2026-09-13-timeline-release-debt-medium-design.md` で決定した。調査で判明した仕様書との食い違い:

- 13: `TimelineLayerBase.Init` が新規レイヤーに 0 フレームキーを作っている。エラーになるのはキーを削除・移動した場合と、0 フレームにキーの無い XML を読んだ場合のみ
- 11: ライブ演出は `HistoryManager.BeforeEdit` を呼んでいないだけで、呼べば Undo と自動登録の両方が既存経路で効く

## 進め方

- 高 1〜8 は「対応する / 仕様として明記して許容する」を項目ごとに決め、対応するものは `superpowers:writing-plans` で計画を作って `plan-review` にかける
- 中・低は対応しない場合も `docs-site/timeline/compatibility.md` の「その他の制限」へ明記しておく
