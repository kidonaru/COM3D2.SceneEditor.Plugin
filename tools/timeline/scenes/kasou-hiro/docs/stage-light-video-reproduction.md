# 動画を参考にステージライトを再現する

「仮装狂騒曲 篠澤広」で得た再現手順。動画を観察して近似し、ゲーム画面で比較するためのガイドであり、光源の3D座標を自動復元するものではない。2026-09-12更新。区間固有の値・適用履歴は末尾の[区間別の記録](#区間別の記録)から参照する。

## 基本方針

- **光を識別してから動きを作る。** 別々の光のフェード、カメラ移動、照射軸の回転を分ける。明るい場所が変わっただけで、同じライトの軌道と判断しない。
- 点灯中は一方向の回転とフェードイン／アウトを基本にする。ただし、動画にない大きな横振り・往復・急停止・細かな明滅を加えない。
- カット先頭で点灯途中、末尾で残光がある場合もある。区間端を一律にアルファ0へ揃えず、前後のカットとつなぐ。
- 位置・向き・必要な形状変更は消灯中に準備する。点灯中に元の姿勢へ戻さず、消灯後は最後の角度を保持できる。後続キーは現在のXMLで確認する。
- **動画との見た目、補間の数値、XMLの保持を別々に検証する。** 角度が設計どおりでも、光の読み取りが違えば自然な再現にはならない。

## 1. 対象と動画時刻を確認する

原本のバイト列・SHA256・更新状態を記録し、版、FrameRate、レイヤーのClassName / SlotNo、登録名、対象灯の全キーを抽出する。キーがないフレームも、前後のキーから状態が適用される。直前の姿勢・消灯状態・後続キー・親の自動設定を確認する。

| このシーンで確認した項目 | 値・注意 |
| --- | --- |
| 対象 | `StageLightTimelineLayer / SlotNo=0`、`Transform/Type=StageLight` |
| 確認した形式 | version 33、タイムライン30fps |
| 照明の参照動画 | `仮装狂騒曲 篠澤広2.avi`、60fps |
| 時刻の補正 | StartOffsetTime=0、Video.StartTime=0.17秒 |
| ピンク / シアン | RGB `(1, 0.25, 0.7)` / `(0.18, 0.95, 1)` |

これは確認済みファイルの値であり、現在の原本から読み直す。別の「公式振付動画」も登録されているため、`Enabled=true`だけで参照動画を選ばない。頭上の太い光はStageLight、客席を横切る細い光はStageLaserとして観察した。`LightTimelineLayer`や`.menu`モデルのビーム材質同期とは対象が異なる。

```text
動画時刻[秒] = FrameNo / FrameRate + StartOffsetTime + Video.StartTime
```

時刻の符号は[MoviePlayerImpl.targetSeekTimeMs](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/MoviePlayerImpl.cs)と照合する。まず前後のカットを含めて約0.1秒刻みで見て、点灯・消灯・光の識別が曖昧な箇所を1F刻みで追う。

60fps動画と30fpsタイムラインでは元フレームを2枚おきに抽出できるが、シーク後に選ばれた先頭フレームの時刻と丸めを確認してからラベルを付ける。fps変換後の画像番号を元のフレーム番号とみなさない。可変フレームレートや整数比でない動画は提示時刻で対応させ、同じタイムライン位置のゲーム内動画プレビューとも照合する。

## 2. 光を識別し、ライト別に観察表を作る

全体画像と光軸の拡大画像を併用する。拡大だけではカメラ移動やカットを見失いやすい。ライト番号への割り当ては観察後に行い、「右端のピンク」などの仮名で記録する。

| 観察対象 | 確認すること |
| --- | --- |
| トラス・舞台端・固定された灯体 | カメラによる画面全体の移動と、光だけの変化 |
| 光軸の上部と下部 | 同じ光の傾きが連続して変化しているか。明るい領域の中心だけを追わない |
| 複数の位置で同時に見える光 | 同色でも別ライトの可能性。点灯の重なり |
| 各位置の明るさ | 軸の移動が小さく明るさが増減するなら、独立したフェードとして検討 |
| 消灯・再点灯・カット境界 | 別の位置に現れた光を、根拠なく同じ軌道で結んでいないか |

各光の点灯開始、明るさの頂点、保持、減光終了、画面位置、軸の傾きを表にする。動画で見た事実と、3D座標・角度・アルファへの近似値を分ける。露出・ブルーム・背景色の影響があるため、画面の明るさからアルファを直接逆算しない。色だけを直す場合はRGBに限定し、アルファや動きを保持する。

BPMは観察の目安にとどめ、全灯を同じ周期や頂点へ揃えない。光の識別が曖昧なら、回転速度やライト数を決める前に映像を再確認する。

**1342Fの教訓:** 別々の光の切り替わりを2灯の左向き移動と誤認し、+1.8度/F・+2.4度/Fの横振りを加えて不自然になった。最終的には5灯を分け、ほぼ縦向きの緩やかな回転と独立したフェードへ変更し、ユーザーから「良さそう」と確認を得た。採用した-0.15度/Fや5灯という本数も、このカットの近似値であり既定値にはしない。[詳細・採用設定](stage-light-video-correction-1342.md)

## 3. 配置・回転・フェードを設計する

### 回転と区間のつなぎ

一度の点灯ごとに開始姿勢、回転方向、点灯開始、頂点、消灯完了を決める。基本はアルファの単調増加と単調減少で、複数回の点灯は消灯区間で分ける。一定速度の一軸掃引なら次の式で設計できる。

```text
EulerX(f) = 基準角度 + 回転速度[度/F] × (f - 基準F)
EulerY / EulerZ = 点灯中は固定
```

EulerZだけの変更を横方向の傾きと決めつけず、実際のビーム軸で確認する。このシーンで使った `EulerX=90-lean, EulerY=90, EulerZ=0` は、lean=0で下向きになる配置の例。別のカメラや奥行き方向の掃引へそのまま使わない。複数軸では各成分が単調でも、画面上の一方向性は保証されない。

カット先頭が点灯途中なら、その明るさを維持する。末尾の残光と次の1Fを確認し、次の区間を編集する際は以前の消灯境界も再検討する。数値復元のために点灯中の姿勢を急に戻さない。

### 位置・長さ・太さ

番号で画面の左右を決めず、対象フレームの描画カメラ・画角・座標系から判断する。`WorldToViewportPoint`で灯体と光軸を投影し、`ViewportPointToRay`と仮の舞台奥行き平面の交点を配置候補に使える。ただし、奥行きの復元や光の識別の証明にはならない。カットごとに確認し、同じ画面位置を全フレームへ固定しない。

光が見えない場合は、次の順に調べる。

1. 実行時のキー、色・アルファ、可視性、親の`autoPosition / autoRotation / autoColor / autoVisible / autoLightInfo`。
2. 光軸と有効長 `SpotRange × RangeMultiplier`。末端には減衰がある。
3. 背景・舞台による遮蔽。ZTest無効は切り分け用に限り、最終配置で奥行き関係を確認する。
4. 画角に対する太さ。SpotAngleだけでなく長さ・CoreRadius・減衰も見る。

親設定の変更はグループ全体へ及ぶ。個別設定が使える登録済みの消灯灯を検討し、位置・形状は再現に必要な対象だけ調整する。過去に使ったZ=1、SpotRange=13などを既定値にしない。

## 4. XMLと補間を編集する

対象は `ClassName + SlotNo + FrameNo + Transform/Name` で限定する。`Transform`直下のValueだけを読む。子孫検索ではタンジェントや文字列のValueが混ざる。

| StageLightの0始まりの添字 | 内容 |
| --- | --- |
| 0〜2 / 3〜5 | 位置XYZ / Euler XYZ |
| 6 | 今回の編集では使用せず保持 |
| 7〜9 / 10 / 11 | RGB / アルファ / 可視性 |
| 12 / 13 | SpotAngle / SpotRange |
| 14〜22 | 範囲補正・減衰などの描画設定。必要な変更以外は保持 |

確認したStageLightは23値。版・型が異なる場合は[値の定義](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/TransformData/TransformDataStageLight.cs)と[適用処理](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/TimelineLayer/StageLightTimelineLayer.cs)を優先する。位置・Euler角・SpotAngle・SpotRangeはHermite補間、色は`Color.Lerp`、可視性は区間の始点側の値。可視性だけではフェードにならず、回転タンジェントを変えても色のフェード曲線は変わらない。

| 落とし穴 | 対処 |
| --- | --- |
| 正規化タンジェントを角速度として扱う | [TangentData](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/TangentData.cs)のnormalizedValueは基準勾配への倍率。勾配の度/秒と設計の度/FはFrameRateで換算する |
| 全成分の接線・SmoothBitを置き換える | 一定速度なら変化する回転成分の正規化接線を1にし、そのsmoothビットだけ解除する。Euler XYZは3〜5、マスク56。他成分と停止端点は個別に扱う |
| 1F間隔でも通常のHermite式だけで検証する | Delay / Advanceは勾配と再生区間を変える。境界前後を実機評価する |
| キーを間引いて元の設計値を報告する | 設計表、生成キー、実際の補間値を区別し、フェードも再評価する |
| 360度正規化を全て同じ動きとみなす | 90と-270の姿勢は同じでも補間経路は違い得る。連続角度と中間フレームを確認する |

1F間隔の扱いは[TimelineLayerBase.UpdateTangent](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/TimelineLayer/TimelineLayerBase.cs)、差分ゼロの扱いは[TransformDataBase.UpdateTangent](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/TransformData/TransformDataBase.cs)、再生区間の調整は[MotionPlayData.Setup](../../../../../source/COM3D2.SceneEditor.Plugin/Timeline/MotionPlayData.cs)を参照する。

1153〜1211Fでは1211/1212Fの隣接キーで末尾が減速し、1210→1212Fの2F区間へ変更した。間引き後の1211Fのアルファは設計表0.65に対し実機0.34375となった。「終端キーを常に削除する」という規則にはせず、実際の隣接間隔と評価値から決める。[検証記録](stage-light-video-1153-1211.md)

## 5. 候補を検証し、保存する

1. **候補を生成する。** `tools/timeline/work/kasou-hiro/<task-id>/`へ保存し、既存キー・他レイヤー・登録・未知要素・文字コード・BOM・改行を保持する。変更する値と保持する値を明示する。
2. **XMLを検査する。** 構文、登録との対応、採番、値数、有限数値、重複、対象外差分を確認する。基本検査は下記コマンド。StageLightの23値や補間は別途検証する。
3. **ゲームの未保存状態を保持する。** 現在のTimelineManagerと対象レイヤーを取得し直し、ディスクとキー単位で照合する。レイヤーと表示フレームを退避し、必要な対象キーだけを合成する。他レイヤーをシーン再ロードで破棄しない。
4. **見た目と数値を比較する。** 点灯前・頂点・減光・カット前後を動画と同じ時刻で見る。短い区間は全整数フレームで回転方向・角速度・フェードを評価し、境界や中間フレーム、対象区間外も確認する。
5. **原本へ反映する。** 書き込み直前に原本の更新を照合し、同じフォルダーに一意なバックアップを作る。バックアップ一致、保存後の候補一致、XML再読を確認する。
6. **記録して表示を戻す。** 変更内容、対象外への影響、検証範囲、ハッシュ、バックアップの正確なパスを残し、ゲームの表示フレームを元へ戻す。

```powershell
python tools/timeline/scripts/inspect_timeline.py '対象.xml'
```

ゲームでは、利用中のAPIを確認したうえで`ToXml()`で退避し、`FromXml()`で候補を入れ、`ApplyCurrentFrame(true)`で再生データを更新した。古い参照ではキーが0件になった例がある。REPLがリセットされたら退避変数も残っていると仮定しない。

文字列差だけで未保存変更を判定せず、レイヤー・フレーム・名前・型・直下の値を照合する。Euler角の周期比較は姿勢の照合に限り、補間経路の確認を省略しない。JSONとの照合ではタプル／配列などの型も揃える。

「既存キーを保持」「区間外の可視状態を保持」「区間外の全数値が同一」は別の条件。消灯中の位置・角度が変わる場合も記録し、境界キー追加による過去の自動タンジェントへの影響を調べる。整数フレームの数値検証は、動画との画面一致や小数フレームを含む全時刻の保証とは分ける。
