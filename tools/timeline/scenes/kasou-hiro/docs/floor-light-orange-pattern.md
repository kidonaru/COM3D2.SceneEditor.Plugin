# 354フレームまでの床ライトのオレンジ点滅・フェード

2026-09-09、`仮装狂騒曲 篠澤広127.xml`の床ライト24個を調整した記録。現在は、動画から拾った点灯配置にユーザーがフェードを加えたXMLを基準とし、354フレームまで延長済み。

## 現在のパターン

**4フレームで0→2.5、次の4フレームで2.5→0、4フレーム休止**の12フレーム周期。点灯するライトの組み合わせは各パルスで変わる。

- 対象：`ModelMaterialTimelineLayer` / `SlotNo=0`。
- モデル：`kdnr_midnight_floor_light_i_.menu`と`(2)`〜`(24)`。接尾辞なしを番号1とする。
- 材質：`CM3D2_電飾 | マゼンタ`。名前に反して今回の発光色はオレンジ。
- 発光色：`RGB=(1, 0.24, 0.015)`、最大発光強度：2.5。
- 操作する値：`Transform`直下の`Value`の21〜23が発光色RGB、41が発光強度。材質の値数は49。
- ユーザー修正後のキーは`InSmoothBit` / `OutSmoothBit`がともに`562949953421311`で、明示的な`InTangents` / `OutTangents`はなかった。複製時もこの設定を保持する。
- ユーザー修正後のXMLには、初回に置いた258・316の保護キーはない。古い手順に従って復元しない。

以後は最新XMLを正とし、独自の直線補間や古いタンジェントへ戻さない。0〜109フレームの回転など、対象外のキーは保持する。

対象の`Bone`を色・補間設定も含めて複製した。既存部分に構造差分がないこと、追加キーが複製元と一致すること、終了時に全灯消灯することを検証済み。`inspect_timeline.py`はエラー・警告とも0。GameViewでも350の点灯と354の消灯を確認し、表示を354へ戻した。

## 動画から点灯位置を拾った方法

参照は`W:\COM3D2\PhotoModeData\BGM\仮装狂騒曲 篠澤広2.avi`。動画時刻は`frame / 30 + 0.166666672`秒で求める。ffmpegで259〜315フレーム相当を30fps、960×540へ抽出した。

円周上のライト位置を画像上で拾い、カメラの緩やかな動きに合わせてサンプル位置を補正した。各ライトの近傍で赤成分から青・緑の寄与を引いたスコアを取り、点灯開始から数フレームの中央値を比較した。オレンジ装飾、人物、ビームによる誤検出があるため、画素値をそのまま発光強度にはしなかった。

初回の約36フレーム周期・6個に1個を暗くする近似では点滅を取りこぼしていた。細かく比較すると、動画上では264、276、288、300、312付近に点灯し、主に5〜6フレーム続いていた。その後ユーザーがフェードへ修正したため、**現在のXMLのピークは266、278、290、302、314**。動画観察時の点灯開始と混同しない。

動画から拾った当初の組み合わせは[floor-light-orange-pattern.json](../plans/floor-light-orange-pattern.json)に保存。映像とゲームのカメラ・配置差や遮蔽があり、位置対応は近似である。

**JSONはユーザーのフェード修正前の参考資料であり、最新XMLを再生成するための確定データではない。** 編集は最新XMLのキー、色、補間設定を優先する。

## 間引きの扱い

ユーザーのフェード修正前には、259〜315の720キーを439キーへ減らした。材質値と補間情報が前後とも同じ中間キー281個だけを除去した結果であり、439は現在のキー数ではない。

一定値区間の中間キーは省けるが、フェードの始点・ピーク・終点や、一定値を保つ区間の終点は残す。終点を消すと次のキーへの補間が早く始まることがある。現在のXMLを古い点滅に戻すような間引きはしない。

## 1フレーム間隔のキーに注意

当初は毎フレームにキーを置いたが、XML上で264を点灯としていてもGameViewでは消灯し、266では点灯した。

`source/COM3D2.SceneEditor.Plugin/Timeline/MotionPlayData.cs`の`PlayDataBase.Setup`には、隣接キーに対して`SingleFrameType.Delay`の場合に開始位置を後ろへ移す処理がある。今回の症状は2フレーム間隔へ整理すると解消し、264の点灯をGameViewで確認できた。

短い点滅だからといって毎フレームのキーを増やさず、単一フレーム処理と実際の表示を確認する。2フレーム間隔は当初の点滅版での対処であり、現在の4フレーム単位のフェードを2フレーム刻みへ増やす必要はない。
